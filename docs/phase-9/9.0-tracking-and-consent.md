# 9.0 Tracking and consent

## What it does

- **Nothing optional runs before the visitor agrees.** The page only sets Google Consent Mode v2 defaults (all denied,
  no network request). The Google tag, the Meta Pixel and the ad click identifiers are added only after the matching
  consent.
- **Two categories.** _Analytics_ = Google Analytics 4. _Marketing_ = Google Ads, Meta Pixel, `gclid`/`fbclid`.
  Accept all and Reject all look the same. The choice is kept in localStorage (`elzora:consent`) for 6 months, then
  the banner asks again. "Cookie settings" in the footer reopens it.
- **Withdrawing** a category deletes the tools' cookies and reloads the page, which stops their scripts.
- **No tool configured = no banner and no tracking.** Each tool is switched on by its own ID (see `.env.example`):
  `NEXT_PUBLIC_GA4_ID`, `NEXT_PUBLIC_GOOGLE_ADS_ID`, `NEXT_PUBLIC_GOOGLE_ADS_LEAD_LABEL`, `NEXT_PUBLIC_META_PIXEL_ID`.
  They are inlined at build time, so redeploy after changing them.

## Event map

| Event                    | Fires when                                             | Goes to                                 |
| ------------------------ | ------------------------------------------------------ | --------------------------------------- |
| `page_view`              | each route (once per path and tool)                    | GA4, Meta `PageView`                    |
| `view_journey`           | the scroll journey crosses the middle of the screen    | GA4                                     |
| `journey_station_1`..`5` | station reached (once each)                            | GA4                                     |
| `planner_start`          | the planner opens                                      | GA4                                     |
| `planner_step_1`..`7`    | step shown (once each)                                 | GA4                                     |
| `lead_submit`            | the server saved the request (once per reference code) | GA4, Google Ads conversion, Meta `Lead` |
| `whatsapp_click`         | any link to wa.me / api.whatsapp.com                   | GA4, Meta `Contact`                     |

Parameters are limited to `locale`, `location`, `trip`, `source`; values that look like an email or phone number are
dropped. Names, emails, phones and free text are never sent.

## Click identifiers

`gclid` and `fbclid` are read from the landing URL and saved in sessionStorage **only after marketing consent**
(until then they wait in memory for that page view). They are sent with the lead and stored in `leads.gclid` /
`leads.fbclid` (migration `0006_lead_click_ids.sql`), shown in the dashboard lead page, the CSV export and the team
email ("Ad click ID": Google Ads / Meta, not the value). Run `npm run db:migrate` before deploying.

## Where the code is

- `src/lib/consent/` consent rules and the store; `src/lib/analytics/` config, event rules, browser loader
- `src/components/consent/` banner, footer button, `Tracking` (loader, page views, WhatsApp clicks), `TrackOnView`
- Events are fired in `TripPlanner.tsx` and `JourneyAnimated.tsx`; `JourneyShell.tsx` adds `view_journey`
- Tests: `src/lib/consent/consent.test.ts`, `src/lib/analytics/events.test.ts`, attribution tests in `misc.test.ts`

## How to verify (needs the real IDs; this is the open task in TASKS.md)

1. Set the IDs, build, open the site in a private window. **Network tab: no request to googletagmanager.com,
   google-analytics.com or facebook.com/connect.facebook.net before you click anything.**
2. Reject all: still nothing. Accept all: the Google tag and the pixel load, `page_view` appears.
3. Google Tag Assistant: Consent Mode shows `denied` by default, then `granted` after accepting.
4. Meta Events Manager > Test events (or the Pixel Helper): `PageView`, then `Lead` on a test request.
5. GA4 DebugView: the events above. Google Ads: mark the conversion action's tag status after a test lead
   (add `?gclid=test1234567890` to the URL after accepting marketing and check the lead in the dashboard).
6. Footer "Cookie settings" > untick > save: the page reloads and the `_ga*`, `_gcl_*`, `_fbp` cookies are gone.
