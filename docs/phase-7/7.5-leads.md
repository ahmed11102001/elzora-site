# 7.5 Leads (dashboard)

- `/leads`: inbox with status tabs (counts), "Follow-up due" tab, search (name, email, reference), filters
  (language, country, requested trip slug), pagination (25), CSV export (permission `leads.export`).
- `/leads/<id>`: full request, trip, UTM and consent, status change, follow-up date, private notes, timeline.
- Statuses: `new, contacted, qualified, proposal_sent, converted, lost`. Every change is logged by the database
  triggers from 0002 (who: from 0004 via `app.actor_id`); the first move out of `new` (not to `lost`) stamps
  `first_contacted_at`, which 7.7 uses for response time.
- Notes and follow-ups: notes are `lead_activity` rows of kind `note`; the date is `leads.next_follow_up_on`.
- Audit log: `lead.status`, `lead.note`, `lead.followup`, `lead.export` (ids and counts only, no personal data).
- Export: verified session + `leads.export`, otherwise 404. Filters apply (status, language, country, trip). Max 5000 rows.
  The token endpoints from Phase 6 still work for scripts.

Apply: `npm run db:migrate` (adds 0004). No new environment variables.
Test: send a lead from the planner, open it, move it through every status, add a note and a date, export.
Not here: partner assignment (7.6), KPIs (7.7).
